# Endless pass-through diagnostic

This patch leaves the SDK's left and right floating-point audio buffers unchanged.
It adds no gain, filtering, crossfeed, modulation, clipping, or sample delay.
All knobs and the left footswitch are ignored. The state LED is dim white.
The right footswitch still controls the firmware's bypass behavior.

Mono input handling belongs to the pedal firmware. This patch does not duplicate
or average channels. Hardware converters and firmware buffering still contribute
latency and may change levels even though the patch preserves samples exactly.

## Build and test

From the repository root on Ryan's Mac:

```sh
make -C example -f diagnostic/Makefile test
make -C example -f diagnostic/Makefile TOOLCHAIN=/Users/ryanveitch/nodejs/polyend/agt15-2/bin/arm-none-eabi- all
```

Output: `example/build-passthrough/endless_passthrough_<timestamp>.endl`.
The separate build directory preserves saved chorus builds. For a clean rebuild,
run `make -C example -f diagnostic/Makefile clean` first. Header dependencies are
not generated by the SDK Makefile, so clean after changing SDK headers.

The diagnostic selects its own implementation and reuses the existing SDK wrapper
and linker script. The default chorus source and build selection are unchanged;
the existing duplicate definitions in the chorus still need separate repair.
The ARM linker emits an RWX LOAD-segment warning because the existing linker
script puts code and data together in RAM. That script is unchanged.

The host test checks distinct left/right signals, signed zero, full-scale samples,
empty and partial blocks, every knob at minimum/center/maximum, both left-foot
switch actions, and the identifying LED. It exits on completion. It does not
validate the pedal's analog path or firmware.

## REW comparison

Keep mono TS input wiring, stereo output breakout, Alpha 8 gains, 48 kHz,
-24 dBFS stimulus, and channel 3 loopback reference unchanged. Preserve the
original raw captures; keep timing offset zero and calibration None.

After loading this diagnostic, capture both bypass and engaged states to avoid
confounding a patch reload with the comparison. Suggested names:

- `Endless passthrough bypass L 48k take1` (repeat as take2)
- `Endless passthrough engaged L 48k take1` (repeat as take2)

Use REW output/input 11 and reference output/input 13 for the left channel.
Measure right separately with input 12. Record mono/stereo boot mode and the
binary filename/hash. An engaged white LED helps identify the loaded patch.

Compare level and delay to the matching direct TS baseline, then compare engaged
to bypass. The existing TS baseline comparison showed approximately +0.19 dB
at 1 kHz and 8.6506 ms added delay for the previously loaded patch's bypass path.
Those observations do not establish the behavior of this new diagnostic.
Do not align away measured hardware delay or normalize away gain differences.
