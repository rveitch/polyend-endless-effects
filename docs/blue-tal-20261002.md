# Slow TAL-inspired blue revision, 2026-10-02

## Approved intent

Ryan accepted the gain-corrected pedal as the current working baseline, commit `24cb3df`. He likes red Mode I and green Mode II, but dislikes the fast blue vibrato. He selected TAL's slower I+II reference and approved a blue-only revision with slow motion around 0.4 Hz, a broader delay sweep and stereo movement, retaining gain, filters, Mix and red/green motion. Build, commit and push are authorized.

## Voicing

Only blue's motion changes: approximately 0.399996 Hz sine, center 3.455 ms and depth 2.135 ms, giving nominal 1.32..5.59 ms delays. Right motion is a quarter-cycle ahead of left, a project voicing choice. Width continues to collapse the wet channels toward their common mid signal. At full width this provides stereo movement; a single output still carries the slower sweep. Actual TS output routing is not inferred.

The rate and depth are guided by [our TAL combined capture](other-modes-reference-comparison-20260929.md). That capture measures effective broadband delay including filtering, so copying its range as a nominal delay target does not guarantee equal transfer response. Quarter-cycle separation is not a claim about TAL's internals. This is a preferred slow extension, not a hardware-authentic fast Juno I+II mode.

Red/green rates, depths, filters, gain and Mix mapping are unchanged. The pedal retains +4.7 dB at noon and above with unity true-dry endpoint. Desktop retains the separate Output trim, avoiding double gain. Mode fades remain 20 ms; fades involving blue naturally reflect its revised sound.

Gain headroom remains the same limitation: stress tests at 0.5 input peak produce 0.686997 output peak, while 0.99 input produces 1.360254. No limiter or new nonlinear stage was added. Host success does not establish pedal CPU/routing or listening acceptance.
